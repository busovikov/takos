# Takos — план MVP (ревизия 4: Go-ядро, трекер-первый, UX зафиксирован)

## Контекст

ФС-нативный трекер задач: вся информация — файлы на диске, утилита организует работу с ними. Интерактивный агент-враппер исключён (`claude --resume` покрывает сценарий). Поведение CLI/TUI спроектировано мок-сессией (решения Д5–Д39, все в этой ревизии инкорпорированы) и является контрактом; схемы: https://claude.ai/code/artifact/78760513-8058-44dc-aa03-5a02f81c4883

## Стек (ревизия: ядро — Go, JS только для web)

- **Go 1.23+** — единый статический бинарник `takos`: CLI + TUI + оба демона (subcommands). Мгновенный старт CLI, кросс-компиляция, scratch-Docker.
- Библиотеки: `cobra` (CLI), `bubbletea` + `lipgloss` (TUI), `fsnotify` (watcher), `yaml.v3` + frontmatter-парсер, `net/http` (API), стандартный `go test`.
- **Web-интерфейс трекера — единственный TS/JS**: React/Vite в `web/`, собирается в статику, встраивается в бинарник через `go:embed`, отдаётся демоном трекера; второй клиент того же HTTP API (фаза C, после MVP).
- Прежний Node-стек (pnpm, Ink, hono, zod, chokidar…) полностью заменён.

Структура репозитория:

```
takos/
├── go.mod
├── cmd/takos/main.go        # бинарник: task-команды, TUI, daemon start…
├── internal/
│   ├── core/                # ядро трекера: resolve, create/move, history, workflow, гейты
│   ├── fsstore/             # atomic write (temp+rename+fsync), lock, jsonl, frontmatter
│   ├── trackerd/            # демон трекера :7434 — watcher, планировщик, правила, реконсилятор
│   ├── runnerd/             # раннер :7433 (фаза B) — адаптеры, headless-сессии, суммаризатор
│   ├── tui/                 # Bubble Tea: лесенка, карточка, карусель, беклог, спринт
│   └── api/                 # типы API + клиент с файловым fallback
├── web/                     # React/Vite (фаза C)
├── docker/
└── install.sh
```

## Workspace — структура данных (контракт)

Два мира: канонические папки задач (неподвижны) и **хендлеры-симлинки** (позиция = состояние). Хендлер — символическая ссылка `T-0005-slug → ../…/tasks/T-0005-slug/` на папку задачи: содержимого нет — нет и дрейфа/регенерации; `cd`/`ls`/`cat` через ссылку попадают в настоящие файлы задачи.

```
.takos/                             # там, где сделали takos task init, как .git — сам репо-каталог не трогается
├── workflow.yaml                   # единственный конфиг: стадии, роли, правила
├── tasks/                          # КАНОН: папка задачи никогда не перемещается/не удаляется
│   └── T-0005-eksport-otchetov-csv/
│       ├── task.md                 # frontmatter (id, repo, priority, labels, automation)
│       │                           #   + ## Objective (человек) + ## Context (агент)
│       │                           #   + ## What is done / ## Docs / ## Testing (handover)
│       ├── plan.md                 # артефакт планирования
│       ├── plan-hand-off.md        # память решений планирования
│       ├── hand-off.md             # память хода реализации (созд. при входе в implementation)
│       ├── reviews/R-00N.md        # раунды ревью: замечания open|resolved|rework|tech-debt
│       ├── history.log             # append-only: <ISO ts> [<actor>] <verb> <args>
│       ├── sessions/               # маркеры headless-сессий (фаза B)
│       └── artifacts/
├── backlog/T-0007-… -> ../tasks/T-0007-…/   # хендлеры-симлинки вне спринтов
├── sprints/                        # всегда РОВНО ДВА: активный + следующий
│   ├── sprint-12/
│   │   ├── sprint.md               # {status: active|next, startedAt, endsAt, lengthDays: 14}
│   │   └── 1-refinement/ … 5-done/ # стадийные папки; в них — хендлеры
│   └── sprint-13/                  # следующий, та же структура
└── archive/sprint-11/…             # закрытый спринт целиком, хендлеры в финальных стадиях
```

### Несколько воркспейсов (A7 + фаза C)

Воркспейс переносим (git-репо), поэтому список воркспейсов живёт вне их — машинно-локальный реестр `~/.takos/workspaces.yaml`: `default: <name>` + `workspaces: [{name, root}]`. `name` — уникальный слаг `[a-z0-9-]` (по умолчанию basename), он же идентификатор в URL API; дедупликация по resolved-пути. Управление: `takos workspace add|remove|list|use <name>`. Неявного воркспейса нет: `takos task init` создаёт воркспейс в `./.takos` (родительская директория — она же `ws.ProjectRoot()`, дефолтный repo задач и cwd агента — не трогается) и сразу регистрирует его.

Демон один на машину и следит за всеми: супервизор N per-workspace инстансов (watcher+снапшот+реконсилятор+планировщик — сегодняшний Daemon), один HTTP :7434. Локи двухуровневые: глобальный `~/.takos/trackerd.lock` + существующий пер-воркспейсный (его же проверяет CLI-фолбэк спринтов — не меняется). Реестр hot-reload'ится fsnotify: `workspace add` правит файл, демон подхватывает без рестарта. Недоступный root — состояние `unavailable` + ретрай по poll-тику, не ошибка. Pid-файл → `~/.takos/trackerd.pid`; команды демона поднимаются до `takos daemon start|stop|status` (`takos task daemon` — алиас).

API с неймспейсом (контракт для веба): `GET /api/status` (демон), `GET /api/workspaces` (список: name, root, state, activeSprint, счётчики), `GET /api/ws/{name}/status|board|events` (SSE — фаза C). `--workspace` принимает имя из реестра или путь к проектной директории (`.takos` резолвится автоматически); приоритет: флаг → `$TAKOS_WORKSPACE` → воркспейс вокруг текущей директории (поиск `.takos/workflow.yaml` вверх); иначе ошибка со списком зарегистрированных. TUI: клавиша `W` — пикер воркспейсов (смена root + reload). Веб: переключатель из `/api/workspaces`, выбор в localStorage, все вьюхи параметризованы `{name}`, live — per-workspace SSE.

Инварианты (чинит реконсиляция):
1. Задача = одна папка в `tasks/`, путь стабилен навсегда (ссылки живут и после архивации).
2. Ровно один хендлер, ровно в одном месте: `backlog/` | `sprints/<s>/<stage>/` | `archive/<s>/<stage>/`. 0 → восстановить из history.log; 2+ → оставить соответствующий history.
3. Стадия/спринт нигде не хранятся как данные — только позиция хендлера; history.log — летопись, не второй авторитет.
4. Хендлер — симлинк с **относительным** target (workspace переносим). Target зависит от глубины: перемещение такосом = создать симлинк с корректным target во временном имени в целевой папке → `rename(2)` на место → `unlink` старого; после ручного `mv` между уровнями битый target чинит watcher/реконсиляция. Не-симлинк в стадийной папке (`cp -r` вместо `mv`) — карантин + уведомление.
5. Закрытие спринта: done-хендлеры остаются в папке → папка целиком в `archive/`; незакрытые хендлеры → следующий спринт в ту же стадию; следующий становится active, создаётся новый next.
6. Разрешение id: хендлер — глоб `**/T-0005*.md`, папка — `tasks/T-0005-*/`.

Любое перемещение хендлера — атомарный `rename(2)` + строка в history.log; все мутации (Tab, CLI, правила, ручной `mv` через валидацию watcher'ом) проходят один валидатор: whitelist переходов + needs/гейты.

## Зафиксированный UX (контракт из мок-сессии)

### Лесенка (`takos task list`, TTY)
Заголовки стадий в одну строку с обрезкой `…` (стадия курсора подсвечена); задача сдвинута на 2 таба × индекс стадии; статус-строка выбранной задачи над легендой; `:emoji_25B6:` — живая сессия. Tab/⇧Tab — переход через валидатор (отказ — строка в статус-баре, ФС не тронута; running не двигается). Live-обновление watcher'ом (внешние mv и правила перерисовывают доску). `n` создание, `Enter` карточка, `b` в беклог (подтверждение), `B` беклог-экран, `S` спринт, `q` выход. Фильтр по `ws.Root` (без задач других repo); `--all`, `--backlog`, `--archive`. В пайпе/`--plain` — таблица, `--json` для скриптов. Первый запуск без workspace — подсказка `takos task init`.

### Создание (`n` / `takos task create`)
Двухшаговое промпт-поле: название (Enter — задача уже создана в первой стадии) → Objective (многострочное, Shift+Enter — строка; Enter/Esc — сохранить, можно пустым). Esc на названии — единственная отмена. repo из корня воркспейса (`ws.Root` — там, где сделали `takos task init`; `--repo` — явный override), p2 по умолчанию, слаг-транслитерация.

### Карточка (Enter)
Секции: Objective · Context · Plan (+resolved) · Hand-off · Review · Сессия (:emoji_2714: finished / :emoji_26A0: лимит / :emoji_23F8: прервана / :emoji_25B6: работает + длительность). Действия — вертикальное меню `:emoji_276F:` с hotkey-колонкой, состав контекстный, первый пункт — рекомендуемое; горячие клавиши мимо курсора; недоступное скрыто. `e` plan.md в $EDITOR (доступен всегда, даже пустой), `t` task.md, Esc назад. `c` add a finding — только на стадии review.

### Сессии агентов (стадийные, именованные)
Пара «задача+стадия» = нативная сессия `T-0005-<stage>#<поколение>`: UUID детерминирован (uuidv5 от имени), поколение — счёт по history.log; первый запуск `claude --session-id <uuid> "<промпт>"`, далее `claude --resume <uuid>`. Интерактив — обычный дочерний процесс (stdio inherit, без PTY), выход → карточка с пересканом. `a` интерактивно / `f` в фоне (headless-роль стадии), `x` прервать (SIGTERM, подтверждение), `l` лог. Политика входа: лимит → всегда `--resume`; первый вход в стадию (сессий ещё нет) → новая. Как только в стадии была **хотя бы одна сессия**, интерактивно (карточка/CLI) в **любой** стадии доступен выбор «продолжить/новая» — прервана и finished одинаково предлагают меню, `--resume` последнего поколения либо свежее с регенерацией hand-off; продолжить — рекомендуемый первый пункт. Headless (`--bg`, роли демона) остаётся детерминированным по стадии: прервана/крэш → продолжает (не терять работу), finished → новая с регенерацией hand-off — кроме planning, где finished тоже продолжает (разговорная стадия); `--new` всюду форсирует свежее поколение. Фоновые роли — анимированный спиннер + счётчик в статусе.

### Стадии, гейты, hand-off
refinement → (Tab) planning: скаффолд plan.md + роль context пишет `## Context`. planning → implementation: гейт `plan-resolved` — ставит человек (`r`/`takos task resolve`), автоматика предлагает после сессии планирования. Hand-off парный артефакту: `plan-hand-off.md` (решения/отвергнутое/вопросы), `hand-off.md` (сделано/состояние репо/дальше/из ревью; создаётся при входе в implementation как выжимка планирования). Регенерация — перед каждой новой сессией стадии; шаблоны выжимок — на ролях в workflow.yaml.

### Review
Вход = цепочка: handover (коммит только изменённых файлов с подробным телом и id задачи; секции What is done/Docs/Testing в тикет) → reviewer (read-only, раунд `reviews/R-00N.md`). «Изменённые файлы» MVP = всё незакоммиченное в репо задачи (одна активная задача на репо). Замечание — блок со статусом; вердикт вычисляется (regex «Verdict:» удалён). `v` — карусель: одно замечание на экран, дифф оформлен, `r/w/t` (resolve/на доработку/техдолг), Tab/⇧Tab по кругу, автопрыжок к следующему open. `c` — своё замечание в текущий раунд. Open-замечания блокируют перемещения. Триаж завершён: есть rework → авто-move в implementation + «Из ревью» в hand-off; иначе → done. Техдолг → авто-задача в беклоге со ссылкой на источник.

### Настройки ролей (экран `,`)
Назначение агентов на роли (context, planner, executor, handover, reviewer, summarizer) — таблица ролей → Enter → двухшаговый пикер «агент → модель», **только из обнаруженных в системе** (`takos agents`: детекция поддерживаемых CLI + их моделей; у opencode — из `ollama list`; ненайденные видны, но не выбираются, с командой установки). Источник истины — секция `roles` в `workflow.yaml` (agent, model, permissionMode, промпт, шаблон hand-off); экран — редактор полей agent/model, ручная правка yaml законна. `workflow validate` и старт демона сверяют назначения с обнаруженным (предупреждение — workspace переносим между машинами); запуск роли с отсутствующим агентом — отказ с подсказкой.

### Спринты и беклог
Автоцикл 14 дней планировщиком демона; окно `S`: статус (начался/день N/закроется), ручное закрытие `c`, правка sprint.md. Просроченное закрытие без демона — реконсиляцией при первом запуске CLI. Экран `B`: секции «следующий спринт» → «беклог», сквозной курсор, `s`/`b` перемещение между ними, `n` создать в беклог, Enter — карточка.

### Отложено (после MVP)
inbox/уведомления, бюджеты циклов (механика §8.4 исходного плана в силе, UI потом); web-интерфейс — фаза C.

## CLI-поверхность (паритет с TUI — контракт)

```
takos task init [--workspace DIR]   # без флага — текущая директория
takos task list [--plain|--json] [--backlog|--archive] [--all] [--stage S] [--sprint S]
takos task show T-0005 [--json] · history · create "TITLE" [-d TEXT] [--backlog|--sprint next] [-p p1] [--repo PATH]
takos task move T-0005 <stage|next|prev|backlog> [--wait]
takos task edit T-0005 [--plan] · resolve T-0005 [--remove]
takos task agent T-0005 [--bg] [--new] [--role R] · cancel · logs [-f]
takos task review T-0005 [R2 --resolve|--rework|--tech-debt] · comment T-0005 "TEXT"
takos task sprint [status] | sprint close [--yes] · take T-0006 [--now]
takos task check T-0005 <name> [--remove] · workflow validate · daemon start|stop|status
takos agents                                  # обнаруженные CLI: версия, статус, модели
takos task role list [--json]
takos task role set <role> --agent A [--model M] [--force]   # валидация по обнаруженному
takos workspace add [DIR] [--name N] | remove <name> | list [--json] | use <name>   # A7
takos daemon start|stop|status                # A7: один демон на все воркспейсы
```

Конвенции: TTY → интерактив, пайп → плоско, `--json` везде; мутации асинхронны (автоматика в демоне), `--wait`/`logs -f` — дождаться; отказ валидатора = ненулевой exit + та же фраза, что в статус-баре TUI.

## Порядок работ

### Фаза A — трекер (Go)
- **A1** скаффолд: go.mod, cmd/takos, cobra, CI (`go build && go test && go vet`), бинарник печатает версию.
- **A2** fsstore + core-схемы: atomic write, lock, frontmatter/markdown-секции, history-грамматика, схемы sprint.md/review-раунда/workflow.yaml + валидация.
- **A3** ядро + file-only CLI: resolve/create/move/history/workflow/expr/гейты; все команды таблицы без демона; детекция агентов (`takos agents`, `role list|set`) — нужна до A6-интерактива. Проверки: create → папка+хендлер+history; move в запрещённую стадию → ненулевой exit, ФС не тронута; триаж ревью двигает статусы блоков; sprint close переносит корректно; workflow validate ловит битые ссылки.
- **A4** TUI (Bubble Tea): лесенка, создание, карточка+меню, карусель, беклог, спринт, настройки ролей (`,`), промпт-поля.
- **A5** демон трекера + watcher (fsnotify): жесты mv (валидация/откат), инварианты хендлеров, реконсиляция (вкл. просроченные спринты), live-доска.
- **A6** интерактивные сессии: именованные `--session-id`/`--resume`, поколения, политика входа, `x`, history-записи. Тесты трёхслойно: (1) чистая логика — uuid-детерминизм, счёт поколений по history, табличная политика входа, argv-фикстуры; (2) mock-бинарник — argv-запись, исходы finished/interrupted, SIGTERM (`x`), kill -9; (3) live-tier `//go:build live` — настоящий `claude` на локальной модели через `ollama launch claude --model gemma4:e4b -- --session-id/--resume …` (враппер-скрипт вместо агента, авто-skip без ollama/claude; сценарий limit остаётся на mock'е — локальная модель лимитов не даёт).
- **A7** мульти-воркспейс: реестр `~/.takos/workspaces.yaml` + `takos workspace add|remove|list|use`; демон-супервизор всех воркспейсов (hot-reload реестра, глобальный лок, `unavailable`-ретрай), API-неймспейс `/api/workspaces` + `/api/ws/{name}/…`; `--workspace` по имени; `W`-пикер в TUI. Проверки: два воркспейса под одним демоном — невалидный mv откатывается в обоих; `workspace add` при живом демоне подхватывается без рестарта; CLI-фолбэк спринтов молчит при живом демоне.

### Фаза B — headless-раннер и автоматика (Go)
- **B1** раннер + адаптеры claude-code/opencode + mock-бинарник (classification, transcript, crash-safety). **B2** суммаризатор hand-off по шаблонам ролей. **B3** демон раннера :7433 + API + файловый fallback + clientToken-идемпотентность. **B4** фоновые роли: context, planner, executor, handover (коммит+тикет), reviewer; цепочки правил, авто-движение по триажу. **B5** пути отказов: limit → resume, ретраи, паузы. **B6** doctor, install.sh, контейнерный режим. Политика зависимостей установщика: обязательных внешних нет (takos — статический бинарник); агентские CLI и **ollama — опциональные**: install.sh их детектит, печатает статус и подсказку установки (`brew install ollama` / curl-скрипт с ollama.com), но не падает без них. doctor проверяет: версию ollama ≥ 0.31 (нужна `ollama launch` с интеграцией claude — маршрут локальных моделей и live-тестов), наличие спуленных моделей для назначенных в workflow.yaml ролей (`ollama/<model>`), версию `claude` (пин против дрейфа флагов). Контейнерный режим: ollama в контейнер не тащим — остаётся на хосте, доступ через `OLLAMA_HOST`.

### Фаза C — web-интерфейс (TS, единственный JS)
React/Vite в `web/`, go:embed в бинарник, отдаётся trackerd; те же проекции, что TUI (доска/карточка/карусель), read-first → мутации через тот же API. Мульти-воркспейс с рождения: переключатель из `/api/workspaces` (выбор в localStorage), вьюхи параметризованы `{name}`, live-обновления — per-workspace SSE `/api/ws/{name}/events`.

## Верификация

- A: полный цикл руками — create → Tab по стадиям с гейтами → триаж (мок-раунд) → done → sprint close; лесенка live при внешнем `mv`; каждый пункт CLI-таблицы в пайпе + exit-коды; невалидный mv откатывается watcher'ом; реконсиляция после «двигали при выключенном демоне».
- B: CI E2E на mock-агенте — полный цикл с ролями (context → plan → resolve → executor → handover-коммит в scratch-репо → reviewer-раунд → триаж → done) + retry-on-limit; один ручной прогон на живом Claude Code.
- CI: `go build && go vet && go test ./...` + E2E.

## Риски

- Дрейф флагов/поведения `claude` (`--session-id`, `--resume`) — фикстурные тесты, пин версии в doctor.
- handover-коммит «всего незакоммиченного» при параллельной ручной работе в репо — документированное допущение MVP.
- Watcher-корреляция unlink+add при mv — окно 500 мс, фолбэк на реконсиляцию.
- Хендлеры-симлинки: Windows-workspace деградирует (developer mode, core.symlinks) — задокументированное ограничение MVP; git хранит симлинки нативно (mac/linux ок).
- Go+Bubble Tea вместо Node: экосистема markdown/frontmatter скромнее — парсеры зафиксировать в A2 фикстурами.
